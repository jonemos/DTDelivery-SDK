# DT Delivery SDK 0.3.18

DT Web Editor에서 게시한 통합레벨을 브라우저에서 보는 SDK입니다. 제공된 테스트 페이지로 모델을 확인하거나 외부 웹 앱에 모델 목록·로딩 진행·액터 선택·카메라·스크립트 공개 속성을 연결할 수 있습니다. SDK Git에는 모델 데이터와 편집기 실행 파일이 포함되지 않습니다.

## 설치 없이 모델 보기

1. [공식 SDK 저장소](https://github.com/jonemos/DTDelivery-SDK)의 ZIP을 쓰기 가능한 폴더에 **전체 압축 해제**합니다. Git으로 받은 폴더도 같은 순서로 실행합니다.
2. `examples/test-server.cmd`를 더블클릭합니다. PowerShell에서는 SDK 루트에서 다음 명령을 실행합니다.

```powershell
.\examples\test-server.cmd
```

3. Chrome 또는 Edge에서 열린 테스트 페이지를 확인합니다. 기본 주소는 `http://127.0.0.1:5183/`입니다.
4. 첫 실행은 기본 게시 저장소에 자동 연결됩니다. 모델이 하나면 자동으로 열리고, 여러 개면 모델 이름을 고른 뒤 **게시본 열기**를 누릅니다. 목록이 비어 있으면 제작자의 게시 완료 여부를 확인하고 **목록 조회**를 누릅니다.

**이 실행에는 Node.js·pnpm·Python 설치나 실행 중 패키지 다운로드가 필요 없습니다.** Windows 10/11의 기본 PowerShell을 사용합니다. 원격 모델을 볼 때는 게시 저장소에 연결할 수 있어야 합니다. 서버 창은 사용하는 동안 유지하고 종료할 때는 그 창에서 `Ctrl+C`를 누릅니다. 다음에도 같은 SDK 폴더의 `examples/test-server.cmd`를 실행하세요.

HTML 파일만 따로 열거나 SDK 일부만 복사하지 마세요. 기본 저장소의 조회 사용자에게는 모델 이름과 이 실행 순서만 전달하면 됩니다. [처음 전달하는 순서와 준비물](docs/guides/18_FIRST_DELIVERY.md)에 전달 메모 양식이 있습니다.

## 다른 저장소나 로컬 청크 연결

**청크 위치**에서 연결 방법을 고릅니다.

| 위치 | 준비할 내용 |
| --- | --- |
| 원격 게시 저장소 | 제작자가 제공한 **SDK 연결 주소**를 입력하고 **목록 조회**를 누릅니다. 같은 저장소의 새 게시본에도 같은 주소를 사용합니다. |
| 로컬 청크 폴더 | **청크 폴더 선택**으로 폴더를 고르고 읽기 권한을 허용합니다. 일반 내보내기는 `delivery-head.json`·`objects`·`releases`가 있는 루트, 게시 저장소는 `levels`가 있는 루트 또는 `levels` 자체를 선택하고 게시 구역을 맞춥니다. |
| 정적 청크 주소 | 일반 청크 내보내기 폴더의 HTTP 주소를 입력합니다. 예: `https://example.com/chunks/`. |

제작자는 편집기에서 레벨을 저장하고 통합레벨에 추가한 뒤 청크를 게시하거나 내보냅니다. 조회 사용자에게 에디터 작업 폴더·Unreal 프로젝트·쓰기용 접속 키를 전달할 필요는 없습니다. 원격 저장소는 공개 읽기와 페이지 origin의 CORS를 허용해야 합니다. 접속 키를 웹페이지·SDK·공개 Git에 넣지 마세요.

테스트 페이지는 새 모델 목록을 기본 10초마다, 열린 모델의 새 게시본을 기본 5초마다 확인합니다. 새 게시본을 검증하고 표시 준비를 마친 뒤 전환하며 카메라·표시 설정을 유지합니다. 갱신에 실패하면 현재 표시를 유지하고 재시도합니다.

마지막 원격 연결과 모델 선택은 브라우저에 저장합니다. **연결 해제**는 저장한 연결과 다음 실행의 기본 자동 연결도 해제합니다. 이후에는 청크 위치와 주소를 지정해 목록을 다시 조회하세요.

## 로딩과 화면 조작

SDK는 metadata를 확인하고 실제 참조하는 에셋을 필요할 때 읽습니다. 요청한 파일의 독립 청크는 최대 네 요청 범위에서 병렬로 읽고, 같은 파일 안의 반복 청크는 한 번만 읽습니다. 각 청크와 완성 파일의 해시를 검증하며 취소·손상 시 부분 파일을 표시하지 않습니다. 참조를 안전하게 선별할 수 없는 구성은 보수적으로 더 넓게 준비할 수 있습니다.

지연 읽기는 미사용 데이터를 삭제하는 기능이 아닙니다. 필요한 데이터의 전송·해시 확인·메시 준비·재질/텍스처 적용에는 시간이 걸립니다. 표시 준비 문구가 끝나더라도 새 시야에서 GPU 업로드가 이어질 수 있습니다. 속도는 모델 크기·캐시·저장소 지연·기기에 따라 달라집니다. 편집기 실행 파일의 로딩 측정값을 SDK의 속도 보장으로 사용하지 않습니다.

왼쪽 아웃라이너에서 액터를 검색·선택하고 오른쪽에서 로드 진행·선택 정보·스크립트 공개 속성을 확인합니다. 뷰포트의 원근/직교·라이팅·표시 메뉴로 화면을 조정합니다. **바운드**는 원본 메시와 함께 액터의 경계 상자를 표시하는 보조선입니다. 기능별 예제는 코드·입력값·실행 결과를 함께 보여 줍니다.

**표시 → 텍스처**에서 사용할 맵과 크기를 선택해 적용합니다. 크기는 **128·256·512px**이며 모든 맵의 최대 표시 크기는 **512px**입니다. 표시 설정은 원본 에셋이나 저장 레벨을 바꾸지 않습니다. 색상 텍스처를 꺼도 Opacity에 필요한 알파는 유지합니다. 메모리 예산 `0`은 자동 선택입니다. [텍스처·메모리 가이드](docs/guides/10_TEXTURES_BUDGET.md)에서 표시 예산과 캐시의 차이를 확인하세요.

가져오기에서 보존한 PBR·UV 반복/미러·배율·오프셋과 베이크 결과를 사용합니다. 편집기·통합레벨·SDK의 외형을 비교할 때는 텍스처 준비 후 카메라·라이팅/언릿·환경광과 강도·Render Quality·맵/크기를 맞추세요. 개인 뷰포트 환경설정 전체가 청크에 저장되지는 않습니다. Unreal 재질 그래프·굴절·WPO·조명 전체의 재현을 보장하지 않습니다.

초기 수평 FOV는 90°, Near/Far는 0.01/2000m, 환경광 강도는 0.2입니다. 화면 크기가 바뀌어도 수평 FOV를 유지합니다. SDK API의 환경광은 기본 꺼짐이며 제공된 테스트 페이지는 보기 쉽도록 환경광을 켜서 시작합니다.

개발 호스트는 공간 경계가 있는 게시본에 거리 기반 자동 언로드를 선택적으로 적용할 수 있습니다. 가까워지면 표시 자원을 다시 준비하므로 실제 이동 범위와 메모리 예산에 맞춰 설정하세요.

## 외부 웹 앱에 넣기

웹 앱 개발에는 Node.js·pnpm이 필요합니다. 아래는 앱 폴더 옆에 SDK 폴더를 둔 예입니다. 제공된 테스트 페이지만 사용하는 경우에는 이 설치가 필요 없습니다.

```powershell
pnpm add ../dt-delivery-sdk
```

```ts
import { DeliveryClient } from '@dt/delivery-sdk';
import '@dt/delivery-sdk/viewport.css';

export async function mountDelivery(canvas: HTMLCanvasElement) {
  const sdk = new DeliveryClient({ canvas });
  const models = await sdk.listModels();
  if (models.length) await sdk.open(models[0]!.id, { progressive: true });
  return sdk;
}

// 화면이나 컴포넌트를 제거할 때: await sdk.dispose();
```

canvas와 부모 요소에 실제 폭·높이를 지정하세요. `source`를 생략하면 기본 저장소를 사용합니다. 다른 연결은 `HttpChunkSource` 또는 `LocalChunkSource`로 지정하고 사용자가 고른 모델 ID로 `sdk.open(modelId)`를 호출합니다. 자동 갱신을 끄려면 생성 옵션에 `autoUpdate: false`를 전달합니다.

| 기능 | 주요 호출 |
| --- | --- |
| 모델 목록·열기 | `sdk.listModels()`, `sdk.open(modelId)` |
| 로딩 진행 | `sdk.progress`, `sdk.subscribeProgress(listener)` |
| 액터 검색·선택·포커스 | `sdk.actors(query)`, `sdk.selectActor(target)`, `sdk.focusActor(target)` |
| 화면 모드·바운드 | `sdk.setViewMode(mode)`, `sdk.viewport.setBounds(enabled)` |
| 거리 기반 언로드 | `sdk.viewport.setSpatialStreaming(options)`, 해제는 `null` |
| 스크립트 공개 속성 | `sdk.scripts.list()`, `sdk.scripts.get(target)` |
| 취소·종료 | `sdk.cancel()`, `await sdk.dispose()` |

[호스트 적용 가이드](docs/guides/17_HOST_INTEGRATION.md)는 Git 패키지 설치·정적 파일 포함·SPA 정리·배포 확인을 설명합니다. [API 명세](docs/API.md), [기능별 가이드](docs/guides/README.md), [페이지 구성](docs/guides/14_PAGE_LAYOUT.md), [예제 소스 개발](examples/web/README.md)에서 상세 계약을 확인하세요. Git 의존성으로 설치할 때는 제작자가 실제 게시한 릴리스 태그를 사용합니다.

## SDK 프로그램 업데이트

1. 실행 중인 테스트 서버 창에서 `Ctrl+C`를 눌러 종료합니다.
2. **사용하던 SDK 폴더의 `update.cmd`**를 더블클릭합니다. PowerShell에서는 아래 명령을 실행합니다.
3. 완료 메시지를 확인하고 `examples/test-server.cmd`를 다시 실행한 뒤 브라우저를 새로고침합니다.

```powershell
.\update.cmd
```

같은 명령으로 SDK runtime·타입·문서·테스트 페이지를 함께 갱신합니다. 다시 clone하거나 별도로 `git pull`을 실행할 필요는 없습니다. Git 사본은 설치된 Git을 사용하며 ZIP 사본은 Git 없이 업데이트합니다. 공식 `main`의 파일 해시를 확인하고 백업한 뒤 교체합니다. SDK 파일을 직접 수정했다면 덮어쓰지 않고 중단합니다. 복구 방법은 [업데이트 안내](docs/UPDATING.md)를 따르세요.

업데이트 대상은 **명령을 실행한 SDK 폴더**입니다. 다른 웹 프로젝트에 설치하거나 복사한 SDK는 해당 의존성/사본을 갱신하고 앱을 다시 빌드·배포해야 합니다. 모델 데이터 갱신은 제작자의 재게시로 이루어지며 SDK 프로그램 업데이트와 별개입니다. 자체 앱 코드·모델·개인 설정은 SDK 폴더 밖에 보관하세요.

## 문제 해결과 전달

| 증상 | 확인할 내용 |
| --- | --- |
| 모델 목록이 비어 있음 | 게시 완료 여부·저장소·게시 구역·네트워크를 확인하고 **목록 조회**를 누릅니다. |
| 원격 읽기 실패 | SDK 연결 주소·공개 읽기·CORS·페이지와 청크의 HTTPS 구성을 확인합니다. |
| 로컬 폴더 권한 오류 | Chrome/Edge에서 올바른 루트를 다시 선택하고 읽기 권한을 허용합니다. |
| 흰색·회색·어두운 모델 | 텍스처 적용 완료·Base Color·언릿·환경광/라이팅 상태를 확인합니다. 가져오기 실패 항목은 제작자가 복구하고 재게시합니다. |
| 원거리 객체가 보이지 않음 | 호스트가 설정한 공간 언로드 범위와 로딩 상태를 확인합니다. |
| 해시·참조 오류 | 제작자가 게시본을 복구한 뒤 다시 엽니다. 청크를 직접 고치거나 검증을 우회하지 않습니다. |
| 서버·업데이트 실패 | 전체 압축 해제 여부와 실행 창 메시지를 확인합니다. 기존 테스트 서버를 종료하고 다시 실행합니다. |

다른 사용자에게는 `https://github.com/jonemos/DTDelivery-SDK.git`, 모델 이름, 기본 저장소 사용 여부 또는 연결 주소/청크 폴더, 실행 순서, 문의 담당자를 전달하세요. [첫 전달 안내](docs/guides/18_FIRST_DELIVERY.md)의 양식을 사용할 수 있습니다. SDK는 MIT 라이선스이며 모델의 배포 권한은 별도로 확인합니다.
