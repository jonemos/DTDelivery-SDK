# SDK 테스트 페이지

전체 SDK의 `examples/test-server.cmd`를 실행하세요. Windows 기본 PowerShell로 미리 빌드한 페이지를 제공하므로 Node.js·pnpm 설치나 시작 시 다운로드가 필요 없습니다. Chrome/Edge에서 기본 주소 `http://127.0.0.1:5183/`을 엽니다.

기본 저장소는 자동 연결됩니다. 모델이 하나면 바로 열리고, 여러 개면 이름을 선택한 뒤 **게시본 열기**를 누릅니다. 제작자가 최신 편집기로 게시하기 전에는 목록이 비어 있습니다. 새 모델 목록은 기본10초, 열린 모델의 새 게시본은 기본5초 간격으로 확인합니다. 카메라·표시 설정을 유지하며 준비 실패 시 현재 화면을 보존합니다.

마지막 연결·모델 선택을 브라우저에 기억하고 다음 실행에 복원합니다. **연결 해제**를 누르면 저장한 연결도 지웁니다. 다른 저장소는 **원격 게시 저장소**에서 제작자가 제공한 SDK 연결 주소를 입력합니다. 통합레벨 ID를 따로 입력하지 않습니다. 저장소 공개 읽기·CORS 권한은 필요하며 비밀키는 입력하지 않습니다.

로컬 청크는 **로컬 청크 폴더**에서 일반 내보내기 루트 또는 로컬 게시 저장소의 루트/levels를 선택하고 읽기 권한을 허용합니다. 게시 저장소는 실제 게시 구역을 맞춥니다. **정적 청크 주소**는 일반 내보내기 폴더의 HTTP 주소를 읽습니다.

상단에는 연결·모델 선택, 왼쪽에는 기능별 실행 예제·액터 목록, 오른쪽에는 코드·입력·결과와 로드 진행·선택 정보·스크립트 공개 속성이 있습니다. SDK 연결·사용 방법은 [SDK README](../../README.md), 함수·타입은 [API 명세](../../docs/API.md)를 참고하세요.

## 업데이트

테스트 서버를 `Ctrl+C`로 종료하고 SDK 루트의 `update.cmd`를 실행한 뒤 서버와 페이지를 다시 엽니다. 설치 도구는 필요 없습니다. [업데이트 안내](../../docs/UPDATING.md)에서 백업과 오류 해결 방법을 확인할 수 있습니다.

## 예제 소스 수정

페이지 소스를 수정하는 개발자만 Node.js24.16 이상·pnpm11.9.0을 준비하고 `examples/web`에서 실행합니다.

```powershell
pnpm install --ignore-scripts
pnpm update @dt/delivery-sdk --no-save --ignore-scripts
node ../detach-sdk.mjs
pnpm exec vite --host 127.0.0.1 --port 5183 --strictPort
```

개발 빌드는 `pnpm build`이며 결과는 `web/dist`에 생성됩니다. 기본 테스트 서버는 공식 SDK가 미리 컴파일한 `examples/standalone`을 사용합니다. 일반 사용자는 이 개발 명령을 실행하지 않아도 됩니다. 페이지를 제거할 때 SDK의 dispose와 listener 해제를 호출합니다.
