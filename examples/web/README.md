# API 연결 테스트 웹페이지

이 페이지는 SDK의 API 서버에서 모델 목록을 조회하고 선택한 모델을 3D 화면에 표시합니다.

## 1. 먼저 API 실행

SDK 루트에서 자신의 청크 위치에 맞는 실행 파일 하나를 선택합니다.

| 청크 위치 | 실행 파일 | 자세한 순서 |
|---|---|---|
| 로컬 폴더 | `local-server.cmd` → 청크 폴더 입력 | [로컬 실행 안내](../../README.md#local) |
| S3 호환 원격 저장소 | `remote-server.cmd` → 준비된 루트 config 사용 | [원격 실행 안내](../../README.md#remote) |

일반 로컬 청크는 delivery-head.json·objects·releases가 있는 폴더를 사용하며 receipts는 필요 없습니다. 원격 CMD는 설정이나 키를 입력받지 않습니다. 실제 원격 설정·ID와 서버 환경변수는 배포 담당자가 준비합니다.

API 창에 `Delivery API listening`이 나오면 그 창을 켜 둡니다.

## 2. 테스트 서버 실행

Windows에서는 상위 **examples 폴더의 `test-server.cmd`**를 실행합니다. 의존성 설치·서버 시작·브라우저 열기가 자동으로 진행되며 주소는 `http://127.0.0.1:5183/`입니다. 이전 테스트 창이 실행 중이면 Ctrl+C로 종료한 뒤 다시 실행합니다.

수동 실행은 **이 examples/web 폴더**의 터미널에서 진행합니다.

```sh
pnpm install --ignore-scripts
pnpm exec vite --host 127.0.0.1 --port 5183 --strictPort --open
```

API와 테스트 서버는 각각의 창에서 실행하며, 종료는 각 창에서 Ctrl+C입니다. SDK 게시·버전 관리용 폴더와 별도의 개발용 clone/ZIP 사본에서 실행하세요.

예제의 `pnpm-workspace.yaml`은 이 폴더만 설치 대상으로 삼고 로컬 SDK 의존성의 내부 폴더 이름을 해시로 생성하도록 설정합니다. Windows 탐색기가 읽지 못하는 마침표로 끝난 폴더를 방지합니다. 이 설정을 함께 사용하도록 `--ignore-workspace`는 붙이지 마세요. 이전 버전에서 이미 생성한 `node_modules`에는 소급 적용되지 않으므로 서버를 종료하고 한 번 정리한 뒤 새 설정으로 설치하세요.

## 3. 모델 열기

화면의 **청크 위치**에서 앞에서 실행한 API에 맞게 **로컬 폴더 / 원격 저장소**를 선택합니다. 처음에는 로컬이 선택되어 있습니다. 같은 SDK의 해당 config에서 **API 주소·scope·토큰을 자동으로 입력**합니다. **목록 조회 → 통합레벨 선택 → 게시본 열기**를 누르세요.

상단 첫 줄에서 API 연결 정보를 입력하고, 둘째 줄에서 통합레벨을 선택해 **게시본 열기**를 누릅니다. 아래 **실행 안내**를 펼치면 선택한 방식의 CMD와 토큰 위치를 확인할 수 있습니다. 조회·연결 결과는 안내 옆의 상태 문구에 표시됩니다.

뷰포트 왼쪽에는 통합레벨과 같은 **뷰포트 옵션 → 원근 → 라이팅 → Render Quality → 표시** 메뉴가 있습니다. 기본 환경광이 켜져 있으며 품질 메뉴에서 강도와 화면 효과를 바꿀 수 있습니다. 왼쪽 아웃라이너에는 원본 레벨의 액터와 통합레벨에 직접 배치한 라이트·도형도 포함됩니다. 선택하면 오른쪽에서 이름·ID·위치·구조를 확인합니다.

공간 정보가 있는 게시본은 준비된 레벨·공간 셀부터 화면에 나타납니다. 오른쪽 **실시간 로드 진행**과 상단 상태는 실제 준비 개수·다운로드량·시간을 표시합니다. 지연 중에는 먼저 준비된 부분을 볼 수 있고 **로딩 취소**로 중단할 수 있습니다. 공간 정보가 없는 이전 게시본은 전체 준비 후 표시합니다. 청크 실패는 완료로 표시하지 않으며 목록 조회 후 다시 열 수 있습니다.

| 입력란 | 로컬 | 원격 |
|---|---|---|
| 조회 API 주소 | 로컬 config에서 자동 입력 | 원격 config에서 자동 입력 |
| API 토큰 | 로컬 dataDirectory의 `.api-token` | 원격 dataDirectory의 `.api-token` |
| 게시 구역(scope) | 로컬 config의 scope | 원격 config의 scope |

기본 주소는 `http://127.0.0.1:18849/`입니다. 원격 청크를 읽어도 API가 같은 PC에서 실행되면 주소는 같습니다. 토큰이 비어 있으면 API를 먼저 실행하고 **목록 조회**를 다시 누르세요. SDK 루트 `.env` 또는 테스트 서버에 전달된 `DT_DELIVERY_API_TOKEN`은 파일 토큰보다 우선합니다. API의 다른 터미널에만 지정된 환경변수나 다른 PC의 API를 쓸 때는 운영자가 제공한 주소·scope·토큰을 직접 입력합니다. 자동 입력된 토큰은 API 주소를 수정하면 지워집니다.

자동 입력은 이 예제의 **같은 PC 테스트 서버**에서만 제공합니다. 토큰을 HTML/JS 빌드 결과나 공개 Git에 넣지 않습니다. 일반 배포 웹페이지와 외부 프로젝트에는 자체 인증을 연결합니다. S3 접속 키는 서버에만 남습니다.

실제 청크 위치는 실행한 API 서버의 설정으로 결정됩니다. 로컬/원격을 바꾸려면 기존 API를 종료하고 해당 CMD를 실행한 뒤 화면에서도 같은 위치를 선택하세요. 선택을 바꾸면 이전 모델·목록·토큰을 지우고 새 방식의 연결 정보를 읽습니다. 연결 정보를 수정한 뒤에는 목록을 다시 조회합니다.

**목록 조회 → 통합레벨 선택 → 게시본 열기**를 누릅니다. 새 청크를 저장하거나 원격 게시를 완료한 뒤에는 API를 재시작하고 목록 조회·게시본 다시 열기를 진행합니다.

큰 모델은 전체 다운로드와 검증 후 표시됩니다. **게시본 준비 중** 옆에 다운로드 용량·청크 요청 수·화면 준비 수·경과 시간이 표시됩니다. 용량이 늘면 진행 중입니다. **로딩 취소**로 중단할 수 있고 오류가 발생하면 상태 문구에 이유가 나옵니다. 완료 후에는 **준비 완료**가 표시됩니다.

토큰은 입력란/메모리에만 보관하고 연결 해제·화면 종료 때 지웁니다. 이 예제의 목록은 첫 페이지입니다. 실제 서비스의 전체 목록에는 pagination을 연결하고, 운영 로그인·토큰 갱신·권한 철회는 프로젝트에 맞게 구성하세요.

모델이 표시되면 [기존 웹프로젝트에 SDK 연결](../../README.md#project)을 따라갑니다. 실제 예제 코드는 [main.ts](main.ts)에 있습니다.
